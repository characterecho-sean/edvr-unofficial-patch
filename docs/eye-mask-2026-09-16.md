Sean's question: can EDVR alter the eye mask the headset reports, to reduce
rendering and DLSS load. His steers the same day: default to the mask the
runtime provides, estimate one when it provides none, and let the user control
it live from the performance menu.

## Mechanisms

**A1. Pass the runtime's mask through under the cull guard.** Today it is
withheld. The mask is a set of rays, the guard's frustum is known, so
projecting into the modified frustum instead of returning empty is a small
change in GetHiddenAreaMesh; whether `hiddenMasksCompatible` guards something
else (the submit crop) must be read before changing it. Worth only what Elite
does with the mesh, which is unobserved.

**A2. EDVR draws the mask itself.** After the game's clear of an eye-sized
depth buffer, draw the mask triangles depth-only at the near value the probe
learned for that target (0 for standard depth, 1 for reversed), colour writes
off, state saved and restored as ui_depth does. Every later draw into that
target fails the depth test in the region; G-buffer writes, the cost class the
cull freed, stop there. This is the only way a live control reaches the game,
it works on routes whose runtime supplies nothing, and it does not depend on
Elite honouring GetHiddenAreaMesh. Compute passes (lighting) and NGX are
unaffected. The mask shape: the runtime's mesh when supplied, else a disc about
the optical axis at the widest frustum edge (hides only what a circular lens
cannot show; 7.5% here), and the user's radius below that as the live trade.
Risk to look for: a halo along the boundary from screen-space passes reading
near depth; the guard inset does not cover it.

**B. Trim the field of view told to the game.** Report narrower tangents and a
size scaled by the span ratio (pixel density kept), and place the game's
texture into the matching sub-rectangle of the full-FOV swapchain in the draw
the port already makes, black outside. That keeps the layer's FOV honest, which
matters because the Oculus runtime ignores a narrower layer FOV. Every
per-pixel cost shrinks with the area, NGX included; the game's culler follows
the reported projection (the cull guard proved it). Live through the size
change, as the guard's staging is (a rebuild, a few seconds). Cost: black
beyond the trim. The same radius could drive A2's disc and B's rectangle as its
bounding box.

| trim (all edges) | area | NGX per pair | saving |
|---|---|---|---|
| none | 1.00 | 3.5 ms | |
| 3 deg | 0.81 | 2.9 | 0.6 ms |
| 5 deg | 0.70 | 2.6 | 0.95 |
| 8 deg | 0.57 | 2.15 | 1.4 |
| outer edge 56.8 to 45 deg only | 0.79 | 2.9 | 0.65 |
| disc bounding box, 45 deg radius | 0.62 | 2.3 | 1.2 |

Model figures on this projection; the frame should save more than the pass
because the game's per-pixel work shrinks too (the fovea flight went the other
way, so measure, do not assume).

**C. Ruled out:** any mask shape reducing NGX (above); the mesh getter as a
live channel (above); OpenXR Toolkit style layer-FOV narrowing as the transport
on Oculus.
