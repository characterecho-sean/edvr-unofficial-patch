# PR 33 review: graphics off switch and write-watch isolation

Reviewed the LiveCopy branch at `ad542134e189ba88ce989560764f4010c2523e03`. The
changes below address reproduced defects in that revision; the LiveCopy
dispatch mechanism stays in place.

## Graphics processing could bypass the off switch

`advanced.d3d11_fixes=0` returned from `hookDevice`, but left the submit-side
exports callable. The existing recovery guard only read the sentinel state. In
a fixture with the setting off, a WARP device created through the proxy
forwarded stock grey clears on both devices, yet `edvrTemporalAa`,
`edvrSharpen`, and `edvrSupersampleResolve` each returned a processed texture.
The new smoke case failed on all three checks before the fix and passed all
three afterwards.

The graphics DLL now latches a shared disable flag before configuring the menu
or installing graphics hooks. Both explicit off and sentinel recovery block
submit-side graphics work, including the menu/FSS composites, eye capture, and
GPU timing starts. Explicit off retains the Present/DXGI hooks for bookkeeping,
while skipping the graphics frame callbacks. The setting still requires a
restart; an INI reload cannot partially reenable the graphics half.

## Unrelated single-step exceptions were consumed

The write-watch handler used its registration as proof that every
`EXCEPTION_SINGLE_STEP` belonged to EDVR, even after disarming. A second
vectored exception handler never received an explicitly raised unrelated
single-step exception, either during or after a watch.

The watch now tracks the pending trap per thread. It consumes its own late step
after a timeout or disarm, and passes unrelated exceptions onward. It also
preserves an existing trap flag and passes hardware-breakpoint events onward.
The regression checks the downstream handler before and after disarm, and
verifies that an actual watched write still completes. The existing
concurrent-writer and abandoned-catch tests also pass.

## A reused event remained readable during publication

The flip ring published a new serial after writing an event, but left the
previous serial valid while overwriting its fields. A deterministic test
observer paused publication after its first field changed: the reader accepted
the previous event while its record was already being reused.

The writer now invalidates the old serial first. Frame draining, recent event
dumps, and the test reader all use the same copy-and-recheck path. The handler
retains catch ownership until its pending event has been consumed and
published, so the frame path cannot rearm another writer in the middle of that
operation. The test observer is compiled only into `vtable_test.exe`, with
`EDVR_VTABLE_TEST`.

## Validation and project impact

The final full build passed, including the write-watch regressions, the
existing LiveCopy stacking tests, and embedded temporal shader creation on
WARP. The graphics-off smoke case passes on two WARP devices. The normal smoke
suite also passes with `--warp`, including stock/fixed clears, hook routing,
view recycling, temporal fallback, resolve, and sharpening. Its log confirms
that auto selected LiveCopy and both context hooks installed in that mode. This
mode explicitly skips NVIDIA-only shading-rate validation; NGX-specific tests
report unavailable on the software device.

These are desktop tests, not a new Elite flight. The Frontier installation was
not changed during this review.

LiveCopy preserves the D3D11 context object's identity, so the OpenXR GPU query
foundation's device/context ownership checks remain applicable. It changes the
forwarding path used by the draw/copy census. After integration, repeat the
Frontier ordering capture and measure dispatch overhead before treating the
earlier timing capture as current. The experimental GPU-query foundation is
still separate from this PR.

The startup shader compilation fix is already shared with main at `ec26970`;
its shader source, embedded-bytecode generator, and shader creation helper are
unchanged by this review.
