## Survey 2 instrument: the log lines and the reader

Still observe-only, still a Home census only. A constant buffer window with
no shadow is copied at its draw into a staging buffer of the dump's own
(`src=staging`, 128 buffers a census, the pool), and so is the vertex or
instance range each star draw reads (4096 bytes a range). The census end maps
them with a **blocking Map**: the CPU waits once for the GPU, on the press and
nowhere else. Windows are dumped whole up to 8192 bytes (b1 is 42 lines). A
window the pool or the context could not read says `src=none skipped=...`
(`pool-full`, `window-unknown`, `deferred-context`, `stage-failed`,
`map-failed`), and the `end` line counts each. Every new line carries
`frame=` (q repeats in each census frame).

| Line | Says |
|---|---|
| `flat star cb: census=3 frame=1 q=633 PS b2 src=staging map=blocking ... shadow=untracked-no-private-copy h=.. data=below` | one block; `src=shadow` was the CPU shadow; `same-bytes-as frame q VS b0` names an earlier identical block |
| `flat star ia: ... slot=1 stride=64 off=0 width=.. class=instance step=1 layout=known` | a bound vertex buffer and the input layout's class for the slot (`unknown`: both ranges are read) |
| `flat star vb: ... slot=1 kind=instance first=3 elems=85 off=192 bytes=4096 wanted=5440 range=capped` | the range read: indexed draws read the index count from the base vertex, an upper bound |
| `flat star geometry: ... star=1/2 d=578223364 R=280954976 R-src=b2 R-b0=280954977 d/R=2.05806 angular-radius=29.071deg ... draws=P0:q467(b),P4:q641(o)` | per star per pass; `(b)` shared b0, `(d)` ring direction, `(r)` radius, `(o)` draw order, `(s)` the only star |
| `flat star colour: ... rgb=1,0.278754,0.0630237 S=164.895 src=P4.psb2[0].yzw@+4 ... surface-peak=2.06765 chroma=agree` | peak-normalised colour and S; the surface's `P1.psb2[0].xyz@+0` beside it |
| `flat star exposure: ... b1[61].z@+984=865.16 b1[61].w@+988=429.439 b1[62].xyz@+992=..` | the exposure-like b1 values |
| `flat star scalars: ... P1.psb2[1].w@+28=0.120688 ... P5.vsb2[1].x@+16=0.088822` | the P1 surface scalars, and P2/P4/P5's star-varying ones |
| `flat star unassociated: ... draws=P3:q564(no-b0-link)` | draws no b0, ring or radius ties to a star (P3 and P2/P4 share a camera-attached b0) |

`python tools\star_survey.py [--file <edvr_gfx_*.log> ...] [--csv out.csv]`
decodes the hex itself (so the first survey's v1 log joins the dataset),
checks it against the DLL's own decoded lines in a v2 log, matches each engine
star to the `truth star` line by radius within 0.1%, and prints the per-star
tables, the best one- and two-variable fits with leave-one-out error (a
relation needs 3 stars, a pair 5) and the near/far series of one star.
`--dry-run` writes nothing. Its fixture, `tools\star_survey_fixture.log`, is
what the formatters write (regenerate: `flat_temporal_test.exe
--write-star-fixture <path>`).

## 2026-10-22: the uniform glow, built (FIRST FLIGHT REPLAYED NOTHING; FIXED; FLOWN PASS)

`visual.star_glow` at 125 to 200 now strengthens the halo of every star by the same factor, flat only, live. At 100
nothing runs and nothing is created (the draw scope asks one relaxed atomic load; the objects below are made at the first
use, and released when the setting returns to 100). The first flight (193420, below) replayed nothing; the fix is not flown.

**The mechanism, in the order the frame runs it** (`src/d3d11/flat_star_glow.cpp`, `flat_star_glow_math.h` for the rules):

1. **S, the star layer.** Each star pass the gates below let through is issued once more right after the game's own issue,
   through `FlatRuntimeDrawScope::uiReissue` (the hook's real call; none of the seven call sites changed). The second issue binds an
   R11G11B10_FLOAT layer S at the target's size as the one colour target, the same depth view, and a clone of the bound
   depth-stencil state with its depth and stencil writes off (the surface pass writes depth). The game's own blend, sample mask,
   viewport, constants, buffers and shader resources stay as they are, so S holds the star's light made by the game's shaders at the
   game's resolution and jitter. S is cleared at the frame's first replay. The targets and state go back after, through the raw
   setters (`vScreenSetRenderTargetsRaw`, and the new `vScreenOMSetDepthStencilStateRaw`), so the binding shadow keeps describing the
   game. Nothing is replayed after the bloom trigger.
2. **H' at the first level.** The trigger draw that writes a half-size target of H is the bloom chain's first level (the HUD feed's
   rule, unchanged). `glowFeedPass` (ui_layer.cpp) builds H' as H plus the HUD (its existing pass), or as a copy of H when no HUD is
   in the layer this frame, and then one more fullscreen pass that reads S and adds it with a blend whose factor is (m, m, m, 0):
   source BLEND_FACTOR, destination ONE, ADD. H' = H + HUD + m·S, m = k - 1, each term once (S holds no HUD). The gate is no
   longer `fix.ui_quality`: the first level is asked for when the HUD layer is live or the star layer holds light
   (`flatUiGlowFeedAsked`). The game's view of H goes back after that one draw; the tonemap and every other reader keep H, and
   no history sees H'. The new pixel shader (`kStarGlowAddPsHlsl`) has one texture at t0, no constants, no sampler; non-finite
   texels read zero and the sum is capped at 60000, as the HUD feed's is.

**Which draws are star passes** (full hashes in `flat_star_glow_math.h`; the pairs of `eye_draw_snapshot.h` plus the jet chain of
`edvr_gfx_20261022_114920` #433-#449): the surface 4D516EF0/147E748F, quad A D95905C1/5BCB6B95, the instanced quads
8BD7C37A/94676B1F, quad B D1281DF4/97DBC87F, the ring 5E417E9D/BD801F2F, the arcs 1F3AD158/BA65C50B, the jet's final add
CFA91824/DE360261 and the flare F7AF326D/952BBB18; the depth pre-pass 0EE43D81 (no pixel shader) and the jet's source
B7413239/66F17D60 (into a depth-less target of its own) are evidence, never replayed.

**The gates** (a pass is replayed only if all hold; the first that fails is its refusal):

| Gate | Refusal |
|---|---|
| it writes an H candidate (`flatHdrCandidateDraw`: R11G11B10F at the scene's extent, depth bound), not the 240x150, 256x256 or 512x512 probe copies | `not-h-candidate` |
| the HDR route's trigger has not come this frame | `after-trigger` |
| a 0EE43D81 pre-pass came earlier this frame, into any target (the frame's marker, kept apart from the run) | `no-pre-pass` |
| the ring only straight after quad A, the instanced quads or quad B in the same run (the ring pair is also the drives' smoke ribbon; a non-star draw into an H candidate ends the run) | `ring-not-in-run` |
| the jet's add only with the jet's source drawn earlier this frame and the bound blend ONE / ONE, ADD; the flare only with the source | `jet-no-source` |

The bloom blur pair CFA91824/DE360261 is the chain's own pass into depth-less targets all frame: it is a jet's add only when it
writes an H candidate, so the chain's blur passes are neither seen nor refused. `no-pre-pass` is not in the design's refusal list; it
is the pre-pass gate, which needed a name of its own.
