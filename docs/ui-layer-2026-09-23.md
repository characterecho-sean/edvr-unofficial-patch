| 0.4187 x 0.2649 | 1078x674 @2576x2544, 2271x1419 @5424x5356 |
| 0.4498 x 0.3726 | 1267x1036 @2818x2784, 2440x1996 @5424x5356 |
| 0.6280 x 0.1367 | 1769x380 @2818x2784, 3407x732 @5424x5356 |
| 0.6783 x 0.1362 | 1354x290 @1996x2121, 1400x300 @2064x2208 |

Left out: powers of two, slivers, eye-sized and larger targets, and a 666x998
surface that kept its pixel size across a 7.5% resolution change.

**Learning: two questions, both needed.** IS IT UI -- ui_depth's classifier
saw GUI draws land in a surface whose create matched nothing -- and DOES IT
SCALE. A GUI-drawn surface is first *pending*, with the internal size it was
made against; the same ratio at an internal size more than 1% different
*learns* it (resized from its next create, and in later sessions); the same
pixel size at such a size marks it *fixed*, never resized (666x998 is one).
All three are kept in `ui_quality_ratios.txt` beside the logs (named in the
ini); the first build's bare ratio lines are not trusted. Needs
`fix.temporal_aa` (the classifier runs under it); the census needs nothing.

**The internal resolution.** The runtime's recommendation for the frame (native
temporal's `beginFrame`, max over eyes; lock-free), before the first frame the
runtime's swapchain sizing made even, times HMD Quality, truncated: 3070x3032 x
0.65 = 1995x1970, x 0.5 = 1535x1516; the flight's FOV-trimmed 2458x2824 x 0.65
= 1597x1835. HMD Quality is the newest `.fxcfg`'s HMDRenderTargetMultiplier,
read on configure and every 5 s on a thread-pool thread, never on the render
thread's frame path or inside a create. Cross-check: the size the game submits;
a disagreement is logged and a create matches against either. Last fallback:
vScreen's measurement.

**The match** (inside CreateTexture2D, the game's creates only): factor =
target / HMD Quality (nothing within 1%, capped at 4); `fss_res`'s ring tracks
the texture, the draw-time backstop rescales its viewports and scissors,
copies touching it are counted. A create of a size decided in the last 2 s
gets that decision again, so a colour target and its depth partner stay one
size though the basis moves between them. Once per size a session the line
names the ratio, the basis and the game's allocating RVAs.

**Blends** (colour kept, alpha = transmittance T, cleared 1): opaque -> ONE,
ZERO / ZERO,ZERO; over, premultiplied over -> ZERO,INV_SRC_ALPHA; additive ->
ZERO,ONE; **multiply** (ZERO,SRC_COLOR or DEST_COLOR,ZERO) -> the colour
equation into the layer, T untouched, and the same draw once more into a
per-channel transmittance M (cleared 1). Composite: `out = L + F * T * M`,
exact for any order (the rig's CPU model; on WARP within 3/255).

**Depth and stencil.** A WRITE (the menu panel: ALWAYS / REPLACE, ref 4, write
0x04): colour to the layer, then the draw once more with no colour target into
the game's own depth target and state (rig: bit-identical). A TEST: the
layer's depth-stencil target, seeded from a copy of the game's by
`ui_deferred_depth.h`'s Seeder (warmed with the layer's shaders) through the
redirected viewport's map inverted, at the frame's first tested draw, again
after a game clear or write, or for stencil bits not yet copied; bound only at
the layer's own size. A stencil test against a view with no stencil plane
(D32_FLOAT) is no test (D3D11 passes it): nothing seeded, said once.
Nearest-sample: exact on pixel-aligned edges, up to half a layer pixel off
elsewhere. Refused and named: read-only, MSAA, array, other-size or D16
targets; a write or a multiply through the curved screen's geometry; a
multiply that writes. The replay's own captures are left to the replay.

## Limits

- What the game draws into an eye AFTER a taken draw lands under it (counted,
  named: "after the UI").
- A sub-pixel viewport origin can cost the layer's last row or column on some
  jitter phases (under the lens mask).
- The 1.25 downsample filters encoded values, the space the game blends in.
- An sRGB door frame or eye view is refused (never measured).
- A refusal with UI in the layer, or a swapped eye, loses one frame's UI in
  one eye, then the layer stands down.
- The on-foot gate lags about a second; with the journal watcher off it never
  holds, and on foot the world goes to the layer again.
