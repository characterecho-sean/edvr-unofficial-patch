## The surfaces

**The rule.** The 129 September logs with a frustum on record: each panel's
first sighting (the depth probe names its depth partner), paired with the
render state it was made in -- the render size and the frustum the game is
handed (`native benchmark workload ... game FOV radians`; the legacy VR log's
`GetProjectionRaw`). A panel is, on both axes, a constant times
U = W / 2 tan(vFOV/2), vFOV = atan(tanUp) + atan(tanDown). One row per
distinct state, worst residual over the panels made in it:

| frustum up/down, render | vFOV | old rule (w/W, h/H) | U rule |
|---|---|---|---|
| Pimax untrimmed ±1.2648, 14 sizes 1995x1970 .. 3901x3226 | 103.3 | ≤ 0.22%, but 19.5% at 2708x2240 and 3901x3226 | ≤ 0.18% |
| Pimax trim 7/5/2 ±1.1778, 1597x1835 (Sean, 5 logs) | 99.3 | 7.85% | 0.20% |
| horizontal trims only ±1.2648, 5 states 1660x1969 .. 2554x3030 | 103.3 | 16.8-26.8% | ≤ 0.28% |
| symmetric and cull-guard frusta ±1.0600, ±0.9657, ±0.8831, 6 states | 82.9-93.3 | 19.3-87.0% | ≤ 0.16% |
| Quest 3 0.9657/1.4281, 5 states 1996x2121 .. 2863x2448 | 99.0 | 8.0-24.9% | ≤ 0.16% |
| Quest 3 trim 2/2/7 0.7536/1.1106, 2307x1652 and 3017x2160 | 85.0 | 90.4-90.8% | ≤ 0.19% |

33 states, 126 log-states (123 logs): every panel within 0.20% there, median
0.04%. Six log-states do not fit: in five the panel was made before a state
change and first seen after it (each fits the earlier state), the sixth is a
2/3-eye buffer, not a panel. `game FOV radians` is the frustum native
temporal's `beginFrame` carries, which the match reads. The constants, in
units of U:

| panel | w x h / U | e.g. Sean trimmed at 0.65 (U 677.9) |
|---|---|---|
| 1 | 0.5291 x 0.7929 | 358x537 |
| 2a | 1.0576 x 0.6608 | 717x448 |
| 2b | 1.0919 x 0.6822 | 740x462 |
| 3 | 1.1371 x 0.9303 | 771x630 |
| 4 | 1.5885 x 0.3408 | 1076x231 (the first build's fifth seed, 1354x290 on the Quest, is this) |

A match is within 0.5% on both axes (the worst residual 0.28%; 2a and 2b, the
nearest pair, 3.2% apart). At a fixed frustum U is linear in W, so the factor
target / HMD Quality makes a panel the rule's size at the target.

**Learning: two questions, both needed.** IS IT UI -- ui_depth's classifier
saw GUI draws land in a surface whose create matched nothing -- and DOES IT
SCALE, in units of U. A GUI-drawn surface is first *pending*, with its render
size and frustum; the same ratio of U at a U more than 1% different
*learns* it (the menu's 1566x880 at U 788.7 and the trimmed cockpit's
1346x757 at U 677.9 are one such panel); the same pixel size at such a U
marks it *fixed*, never resized. All three are kept in
`ui_quality_panels.txt` beside the logs (named in the ini; the first builds'
`ui_quality_ratios.txt` held ratios of the render size and is not read).
Needs `fix.temporal_aa` (the classifier runs under it); the census needs
nothing.

**The internal resolution.** The runtime's recommendation for the frame (native
temporal's `beginFrame`, max over eyes; lock-free), before the first frame the
runtime's swapchain sizing made even, times HMD Quality, truncated: 3070x3032 x
0.65 = 1995x1970, x 0.5 = 1535x1516; the flight's FOV-trimmed 2458x2824 x 0.65
= 1597x1835. HMD Quality is the newest `.fxcfg`'s HMDRenderTargetMultiplier,
read on configure and every 5 s on a thread-pool thread, never on the render
thread's frame path or inside a create. Cross-check: the size the game submits;
a disagreement is logged and a create matches against either. Last fallback:
vScreen's measurement. The vertical field of view is the frame's own frustum
(native temporal's `beginFrame`, eye 0, lock-free, whatever `fix.temporal_aa`
says); before the first frame it is not known, and nothing is matched (said
once). So the surfaces need EDVR's OpenXR runtime: on the Oculus SDK path no
panel is made bigger.

**The match** (inside CreateTexture2D, the game's creates only): factor =
target / HMD Quality (nothing within 1%, capped at 4); `fss_res`'s ring tracks
the texture, the draw-time backstop rescales its viewports and scissors,
copies touching it are counted. A create of a size decided in the last 2 s
gets that decision again, so a colour target and its depth partner stay one
size though the basis moves between them. Once per size a session a `made
bigger` line names the size, the new size, the factor, the panel ratio, U,
the render size and vFOV, and the game's allocating RVAs.

**If the rule never fires**, the 30 s line says so: `N render and depth creates
examined (M the shape of a surface but on no ratio)` with `none made bigger
yet`, the basis it judged by (`internal WxH ..., with a vertical FOV of D
degrees (U = ...)`), and each GUI-drawn surface it missed is named once as
`pending -- ... with 2 tan(vFOV/2) T (ratio R x R of U = X)` -- the numbers
to compare with the table above. No frustum yet: `the game's vertical field
of view is not known yet`. The match never asked: `0 render and depth creates
examined`, or `no surface created since the key went on`.

**Blends** (colour kept, alpha = transmittance T, cleared 1): opaque -> ONE,
ZERO / ZERO,ZERO; over, premultiplied over -> ZERO,INV_SRC_ALPHA; additive ->
ZERO,ONE; **multiply** (ZERO,SRC_COLOR or DEST_COLOR,ZERO) -> the colour
equation into the layer, T untouched, and the same draw once more into a
per-channel transmittance M (cleared 1). Composite: `out = L + F * T * M`,
exact for any order (the rig's CPU model; on WARP within 3/255).

**Depth and stencil.** A WRITE (the menu panel: ALWAYS / REPLACE, ref 4, write
0x04): colour to the layer, then the draw once more with no colour target into
the game's own depth target and state (rig: bit-identical). A TEST: the
layer's depth-stencil target, seeded from a copy of the game's by
`ui_deferred_depth.h`'s Seeder (warmed with the layer's shaders) through the
redirected viewport's map inverted, at the frame's first tested draw, again
after a game clear or write, or for stencil bits not yet copied; bound only at
the layer's own size. A stencil test against a view with no stencil plane
(D32_FLOAT) is no test (D3D11 passes it): nothing seeded, said once.
Nearest-sample: exact on pixel-aligned edges, up to half a layer pixel off
elsewhere. Refused and named: read-only, MSAA, array, other-size or D16
targets; a write or a multiply through the curved screen's geometry; a
multiply that writes. The replay's own captures are left to the replay.

## advanced.ui_replay

`on` (the default, as before): under dlss/dlaa/fsr the deferred UI replay
redraws the holo panels, flight HUD and target sprite after the upscale at the
output size. `off`: they stay in the reconstructed picture with the UI depth
and the reactive mask. Live; logged as `Deferred UI: advanced.ui_replay = on |
off`. The A/B for the cockpit HUD.

## Limits

- What the game draws into an eye AFTER a taken draw lands under it (counted,
  named: "after the UI").
- A sub-pixel viewport origin can cost the layer's last row or column on some
  jitter phases (under the lens mask).
- The 1.25 downsample filters encoded values, the space the game blends in.
- An sRGB door frame or eye view is refused (never measured).
- A refusal with UI in the layer, or a swapped eye, loses one frame's UI in
  one eye, then the layer stands down.
- The on-foot gate lags about a second; with the journal watcher off it never
  holds, and on foot the world goes to the layer again.
