# fix.ui_quality: the UI layer (Design A, phase 1)

## Status

BUILT, NOT FLOWN (2026-09-23). `ui_layer_test.exe --self-test` (102 checks,
WARP) and the full gate are green; no headset session yet.

State: `fix.ui_quality = off | 1.0 | 1.25` (Performance page, default off).
The game's post-tonemap UI draws are rasterised by their own shaders into a
per-eye layer at the door's output size x target, unjittered, and composited
after the upscale and RCAS, before EDVR's menu. Code: `src/d3d11/ui_layer.*`,
`ui_layer_math.h`, `ui_layer_shaders.h`; the wrap in `vscreen.cpp`
(`forwardWithVerdict`); the door in `native_sharpen.cpp`.

Gates, as built (the handoff's numbering, `crisp-ui-handoff.md:1007`):
- UI draws before the pass (the brief's G1): MEASURED by a counter, not assumed
  -- "arrived after their eye's composite" on the gates line.
- G1 (target and view): the layer takes only 8-bit UNORM eye targets. The
  cockpit's holo panels, flight HUD and sprite draw into the HDR target before
  the tonemap (measured 2026-09-06) -- BLOCKED for the layer; they stay with
  the deferred UI replay (below).
- G2 (depth): a draw that tests or writes depth, or stencil, against a bound
  depth target is left in the frame and named. The menus' composites have the
  test off (measured); the 2D screen's composite is UNMEASURED.
- G3 (blend): converted per a table (below); anything else is left, named.
- G4 (jitter): cancelled from the pass's own draw-time jitter; rig-proven for
  all eight phases; the headset is the test.
- G5/G6: per-eye 8-bit targets only; a GUI shader straight into an eye is taken
  as "GUI draw into the eye" if it ever appears.
- G8/G10 (what follows the UI): counted and named ("after the UI").
- Eye identity: ui_depth's order rule, checked against the game's Submit.

The helmet HUD on foot is drawn INTO the 2D screen's texture (the late GUI
composites `screen_motion.cpp` names), so it arrives with the screen.

**Blocked: the HDR families.** The layer is composited after the tonemap; a
pre-tonemap draw redirected into it would lose exposure, tonemap and bloom (the
handoff's own finding, `crisp-ui-handoff.md:156`). Under `dlss`, `dlaa` or
`fsr` the deferred UI replay (`ui_deferred.cpp`) already re-draws them after
the upscale at the output size, with the game's own tonemap -- i.e. at 1.0.
What would unblock 1.25 for them: size that replay's renderer at output x
target and give its combine the box downsample -- a code change on a path with
its own history, not a measurement.

## The design as built, against A1-A8

- **A1.** No eye-target set from the submits: "eye-sized and viewed 8-bit
  UNORM" instead (one cache per Rtv0 binding generation). ui_depth's learned
  surfaces are reused, not re-learned. Verdicts that swallow or re-issue a draw
  (skip, quad skip, intro, backdrop, the scanner's) are left alone.
- **A2.** The layer is door output x target, not "the final size": at 1.0 the
  size DLSS returns (3070x3032 on Sean's rig), at 1.25 3838x3790 -- smoothed
  down by an exact box filter. R8G8B8A8_UNORM. The eye comes from ui_depth's
  per-frame table (first target of a shape = left, `advanced.ui_depth_eyes`
  applied) so the two can never disagree. Cleared at the eye's first draw of a
  frame, not at the boundary. **Alpha holds TRANSMITTANCE, not coverage**:
  D3D11's blend has no constant term, so an opaque draw cannot store coverage 1
  from a shader's alpha; transmittance, cleared to 1, can go to 0.
- **A3.** Raw entry points throughout (the shadow keeps the game's state). No
  depth target is bound; draws that depend on one are left in the frame rather
  than stripped of it. The map is the target-to-layer scale (the native runtime
  crops at the door, not at draw time; the tangent form is in `ui_layer_math.h`
  for a guard lie). Jitter: `nativeTemporalDrawJitter`, the pass's own inverse
  before its sign/lag switches. Blend (colour kept, alpha replaced): opaque ->
  ONE,ZERO / ZERO,ZERO; over and premultiplied over -> ZERO,INV_SRC_ALPHA;
  additive and scaled additive -> ZERO,ONE; refused: other ops, destination or
  dual-source factors, blend factors, alpha-to-coverage, logic ops, an
  alpha-only mask, two render targets.
- **A4.** In `native_sharpen.cpp`'s treat: the runtime calls it for every eye
  after the temporal pass and before EDVR's menu, so the layer lands after RCAS
  with no new ABI. It composites with sharpening off too, and over the game's
  own image when the pass declined (a soft frame, not a missing UI). The layer
  rectangle is the door's input bounds, so a cull-guard crop maps. Compute, one
  dispatch per eye, into an EDVR texture of the region in the frame's 8-bit
  family: `out = L.rgb + F.rgb * L.a`, frame alpha kept.
- **A5.** Not in this phase (`fix.hud_quality` is its own feature).
- **A6.** One key; the debug view is `advanced.temporal_aa_debug = ui_layer`.
- **A7.** Taken draws skip ui_depth's re-issue and reactive mask and the tone
  separation's re-issue; the screen's motion pass stands aside; variable-rate
  shading bound for the eye stands the layer down per draw; ui_deferred is
  untouched (it still sees the draw as a write to the eye's target, as before).
- **A8.** Below.

## What changes order

The only difference from the game's own composite: anything the game draws into
an eye AFTER a taken draw now lands UNDER the UI, and a pass reading the eye
after it (the game's SMAA, a post-tone copy) no longer sees the UI. The
2026-09-06 censuses found nothing after the menu and loader composites but the
copy to the submit texture; the log names anything that does.

## Limits and shortcuts

- A sub-pixel viewport origin clips its own far edge to whole pixels (measured
  on WARP and on the desk's hardware adapter alike: an origin of -0.17 draws no
  last row, +0.39 loses nothing), so a negative cancel loses the layer's last
  row or column on that phase -- the eye's edge, under the lens mask. Not
  compensated: no viewport reaches it without changing the scale.
- The 1.25 downsample filters stored (encoded) values, the space the game
  blends in, not linear light.
- An sRGB-typed door frame or view is refused (never measured); the first
  refusal loses one frame's UI and stands the layer down.
- The runtime's per-eye treatment flags count a layered frame as sharpened.
